# 開発未経験者向け PM／PMO 3年育成プラン

## 1. 前提と育成方針

本計画は、31歳・開発未経験の社員を、3年間でプロジェクトマネージャー（PM）またはプロジェクトマネジメントオフィス（PMO）として自走できる状態まで育成するための計画である。

年齢や性別によって期待値や任せる仕事を変えず、本人の意向、得意分野、実務上の適性を確認しながら役割を選択する。家庭事情、健康、勤務形態などの個別事情は、本人の同意とプライバシーに配慮して確認し、昇格や担当機会の不利益にならないようにする。

### 育成の基本原則

- 開発知識を一度に詰め込まず、担当業務に必要な範囲から学ぶ
- 座学で学んだ内容を、1週間以内にOJTで使う
- いきなり責任者にせず、権限と責任を段階的に広げる
- 成果物だけでなく、報告・相談・リスク察知・関係者との信頼構築を評価する
- 失敗を隠さず早期に共有できることを、重要な成長指標とする
- PMとPMOは優劣ではなく、役割と適性の違いとして扱う

## 2. 3年後の到達目標

### PMルート

小規模または中規模プロジェクトの主担当PMとして、目的・範囲・計画・体制・リスク・課題・品質・コスト・納期を管理し、関係者と合意形成しながらプロジェクトを完了できる。

ただし、重大な契約変更、予算超過、品質事故、要員問題などは、上位PMまたは上司へ適切にエスカレーションできることを条件とする。

### PMOルート

複数プロジェクトまたは大規模プロジェクトのPMOとして、進捗・課題・リスク・品質・会議体・報告資料を標準化し、PMが意思決定しやすい状態を作れる。数値や事実に基づいて状況を可視化し、問題の早期発見と改善提案ができる。

## 3. 1年目：共通基礎とプロジェクト参画

### 1年目の到達目標

- 開発プロジェクトの全体像と基本用語を説明できる
- 指示された作業を期限・品質・報告ルールを守って完了できる
- 議事録、課題管理表、進捗報告などの基本成果物を作成できる
- 不明点、遅延、リスクを抱え込まずに相談できる
- PMとPMOの違いを理解し、自分の志向と適性を言語化できる

### 1年目の座学

| 時期       | 学習テーマ         | 学習内容                                                                                 | 確認方法                     |
| ---------- | ------------------ | ---------------------------------------------------------------------------------------- | ---------------------------- |
| 1～3か月   | IT・開発基礎       | システム開発工程、要件定義、設計、テスト、リリース、運用、アジャイルとウォーターフォール | 用語説明、工程図の作成       |
| 1～3か月   | PM基礎             | プロジェクトの目的・範囲・成果物、WBS、スケジュール、体制、会議体                        | 小規模案件の計画書作成       |
| 4～6か月   | コミュニケーション | 傾聴、質問、報告・連絡・相談、議事録、合意事項の確認                                     | 会議同席後の議事録レビュー   |
| 4～6か月   | 品質・リスク       | 品質の考え方、リスクと課題の違い、変更管理、エスカレーション                             | ケース演習、リスク登録簿作成 |
| 7～9か月   | 数値管理           | 進捗率、工数、予実、遅延、品質指標、簡単な集計                                           | 週次報告資料の作成           |
| 10～12か月 | 振り返り           | KPT、原因分析、再発防止、キャリアと役割選択                                              | 年度振り返り発表             |

### 1年目のOJT

| 時期       | OJTの役割    | 具体的な実践                                                             |
| ---------- | ------------ | ------------------------------------------------------------------------ |
| 1～3か月   | 見学・補助   | 定例会議に同席、議事録作成、タスク一覧の更新、成果物のレビュー補助       |
| 4～6か月   | 一部担当     | 会議の準備と進行補助、担当範囲の進捗確認、課題の一次整理、関係者への確認 |
| 7～9か月   | 小さな責任者 | 1つの作業ストリームまたは小規模改善テーマの計画・実行・報告              |
| 10～12か月 | PM／PMO体験  | PM候補は小規模案件の計画補佐、PMO候補は複数領域の状況集約と報告を担当    |

### 1年目の判定

- PM寄り：不確実な状況でも優先順位を付け、関係者に働きかけて前に進めることに意欲と適性がある
- PMO寄り：情報を整理・構造化し、抜け漏れや変化を見つけ、仕組みで安定化することに意欲と適性がある
- 判定は上司だけで決めず、本人の希望、OJT指導者、関係者の評価を合わせて面談で合意する

## 4. 2年目：選択ルートの実践力強化

### 4-1. PMルート

#### 座学

- ステークホルダー分析と期待値調整
- 要件・スコープ・変更の管理
- WBS、見積り、依存関係、クリティカルパス
- リスク対応、課題解決、意思決定
- チームビルディング、1on1、フィードバック
- 品質計画、受入れ、リリース判定
- 契約・予算・ベンダー管理の基礎

#### OJT

- 小規模案件または案件内の一領域を副担当PMとして担当
- キックオフ、計画策定、週次会議、顧客・関係部署との調整を実施
- 変更要求を整理し、影響範囲・選択肢・推奨案を上位PMへ提示
- 月次でリスクレビューを主催し、対応状況を追跡
- リリースまたは節目の完了報告と振り返りを実施

#### 2年目末の到達基準

- 3～6か月程度の小規模案件を副担当として安定運営できる
- 問題を事実、影響、選択肢、推奨案に分けて報告できる
- 関係者の利害が異なる場面で、合意形成の進め方を提案できる

### 4-2. PMOルート

#### 座学

- PMOの類型：支援型、管理型、指揮型
- プロジェクトポートフォリオと優先順位
- 進捗・課題・リスク・品質の標準管理
- KPI、ダッシュボード、予実管理
- 会議体設計、意思決定ログ、エスカレーション
- 標準化、テンプレート設計、業務改善
- 監査、品質ゲート、ナレッジ管理

#### OJT

- 2つ以上のプロジェクトの進捗・課題・リスクを集約
- 週次または月次のプロジェクト報告資料を作成し、報告会を運営
- プロジェクト間の依存関係、要員競合、共通リスクを可視化
- テンプレートまたは管理ルールを1つ改善し、利用状況と効果を確認
- PM向けに、遅延兆候や意思決定が必要な事項を先回りして提示

#### 2年目末の到達基準

- 複数案件の状況を同じ基準で整理し、経営層または責任者向けに説明できる
- 数値の変化から問題の兆候を見つけ、追加確認や対策を提案できる
- PMの意思決定を支援しつつ、PMの責任を代替しない役割境界を守れる

## 5. 3年目：主担当と専門性の確立

### 5-1. PMルート

#### 座学

- 複雑なステークホルダーとの交渉
- 複数ベンダー、契約、予算、調達の管理
- 組織横断の意思決定と経営報告
- 重大リスク、障害、品質問題への対応
- チームの心理的安全性とパフォーマンス管理
- プロジェクト終了、効果測定、次期計画

#### OJT

- 上位PMの支援を受けながら、小規模または中規模案件の主担当PMを務める
- プロジェクト憲章、計画、体制、リスク、予算、品質計画を作成する
- 定例会議、ステークホルダー報告、変更審査、受入れを主導する
- 重大な問題は初動、影響整理、エスカレーション、復旧計画まで行う
- 完了後に成果・未達・学びを整理し、次の案件へ反映する

#### 3年目末の到達基準

- 目的と制約を踏まえて計画を作り、状況変化に応じて更新できる
- 問題を早期に可視化し、適切な相手へ適切な粒度で相談できる
- チームメンバーを動かし、成果物だけでなくチームの成長も支援できる
- 上位者のレビューを受けながら、案件を最後まで完了させられる

### 5-2. PMOルート

#### 座学

- PMO組織の設計とサービス定義
- ポートフォリオの評価、投資優先順位、経営指標
- 組織横断のリスク・品質・要員・予算管理
- プロジェクト監査と品質ゲート
- データに基づく予測、傾向分析、意思決定支援
- PM育成、コミュニティ運営、ナレッジの再利用

#### OJT

- 部門または複数案件を対象とするPMO業務を主担当として運営する
- 定例報告の仕組み、指標、会議体、エスカレーションルールを改善する
- 案件横断の依存関係、要員、リスク、品質状況を管理する
- PM向けのレビュー会や勉強会を企画・運営する
- 改善施策の効果を導入前後の数値で評価し、経営層へ報告する

#### 3年目末の到達基準

- 複数案件を俯瞰し、組織として優先すべき問題を説明できる
- 状況報告にとどまらず、意思決定に必要な選択肢と提案を提示できる
- 標準化と現場の柔軟性を両立させ、PMが使い続ける仕組みを作れる
- 新任PMやPMOを支援し、知識と判断基準を再現可能な形で伝えられる

## 6. 共通の育成運用

### 週次

- 30分の1on1：困りごと、学び、次週の実践を確認
- OJT指導者との短時間レビュー：成果物、判断、相談タイミングを確認
- タスク・課題・リスクの更新

### 月次

- 60分の育成レビュー：座学の理解、OJTの成果、次の責任範囲を確認
- 成果物を1つ選び、本人の自己評価と指導者レビューを実施
- 「できたこと」「再現できること」「次に試すこと」を記録

### 四半期

- 上司、OJT指導者、本人の三者レビュー
- PM／PMOルートの希望と適性を再確認
- 次の四半期の役割、権限、成果指標を合意
- 必要に応じて、担当量や学習負荷を調整

## 7. 評価指標

| 評価領域           | 観察する行動                                               |
| ------------------ | ---------------------------------------------------------- |
| 進行管理           | 期限、依存関係、優先順位を把握し、遅延前に動く             |
| 品質               | 成果物の目的と受入れ基準を確認し、レビューを受けて改善する |
| 問題解決           | 事実と推測を分け、原因・影響・選択肢を整理する             |
| コミュニケーション | 相手に合わせて簡潔に伝え、合意事項を記録する               |
| リスク感度         | 小さな兆候を見逃さず、早めに相談する                       |
| 主体性             | 指示待ちではなく、次の一手を提案する                       |
| チーム貢献         | 周囲を尊重し、情報共有と相互支援を促す                     |
| 振り返り           | 成功・失敗から学び、次の行動に反映する                     |

評価は「知っている」「一人でできる」「他者に教えられる」の3段階で記録する。単に残業時間や会議での発言量を成果とみなさない。

## 8. 育成上の注意点

- 開発未経験者に、技術者と同じ深さの実装知識を最初から求めない。ただし、専門家へ適切な質問ができる程度の理解は必ず育てる
- 失敗を理由に役割を取り上げるのではなく、影響を限定した環境で再挑戦させる
- 「女性だから調整役が向いている」など、性別に基づく役割付与をしない
- 重要な会議への参加、顧客との接点、意思決定の経験を、本人の希望に反して一方的に制限しない
- 育成担当者を1人に固定せず、PM、PMO、技術リーダー、営業・管理部門など複数の視点を得られるようにする
- 心身の負荷が高い時期は、学習量や担当範囲を調整する。長時間労働を成長の条件にしない
- 評価面談では、人物評価ではなく、具体的な行動・成果物・影響・次の改善行動を扱う

## 9. 最初の90日間の実行例

### 1～2週目

- 本人とキャリア志向、得意・苦手、学習時間、担当可能な範囲を確認
- メンターとOJT指導者を決定
- 開発工程、組織、プロジェクト用語の導入研修を実施
- 参加するプロジェクトと、見学する会議を決定

### 3～6週目

- 会議同席、議事録、タスク管理、成果物レビュー補助を開始
- 週1回、座学テーマを実務成果物で確認
- 指導者が「なぜこの判断をしたか」を説明するシャドーイングを行う

### 7～12週目

- 小さな担当範囲を持ち、進捗・課題・リスクを自分で報告
- 月末にPM体験とPMO体験の双方を振り返る
- 本人の希望を聞き、次の四半期の仮ルートを合意する

## 10. 育成責任者向けチェックリスト

- [ ] 本人が3年後の選択肢と現在の期待役割を理解している
- [ ] 座学とOJTが別々にならず、学習内容を実務で使っている
- [ ] 成果物だけでなく、相談・報告・リスク察知を評価している
- [ ] 失敗しても早期共有した行動を肯定している
- [ ] PMとPMOの両方を体験する機会がある
- [ ] 四半期ごとに本人の希望と役割を見直している
- [ ] 性別、年齢、家庭事情を理由に機会や期待値を固定していない
- [ ] 任せる範囲と、上位者が支援・承認する範囲が明確である
